# 本地与云端持续运行

## 本地启动

在项目目录运行：

```sh
.venv/bin/pyramid-web --open
```

网页读取本地已保存的密钥或环境变量。关闭浏览器不会停止策略；退出网页服务会请求策略完成当前操作后退出。Mac 休眠、断网或关机会中断本地运行，需要持续交易时应保持电脑唤醒并供电。可在终端用下面的命令在服务运行期间防止系统空闲休眠：

```sh
caffeinate -i .venv/bin/pyramid-web --open
```

此命令不能防止合盖、断电或手动休眠。

## Render 启动

按 [Render 部署说明](RENDER.md) 使用仓库的 `render.yaml`。服务使用环境变量密钥、单实例、持久化磁盘和 `pyramid-render` 入口。网页访问需要独立密码。

持久化状态目录必须保留。只启动网页不会自动开启交易；部署、重启后查看已有状态，再从网页启动。不要同时在本地和云端用同一账户交易：进程锁只覆盖同一状态目录，无法协调两台机器。

`/healthz` 只检查网页服务是否存活；策略处于停止或等待人工核查时，网页仍然健康。策略实际状态以控制台的运行状态、心跳和日志为准。

## 故障处理

| 情况 | 行为 |
| --- | --- |
| 网络超时、读取限流、交易所暂时不可用 | 只读请求有限次重试；正常运行阶段持续失败后按 10/20/40/60 秒退避，恢复后继续核查持仓 |
| 读取请求时间戳过期 | 重新校准交易所时间再读取；运行期间每 5 分钟校时 |
| 个别币种价差过大、行情断流或 K 线不完整 | 记录该币种的异常，后续轮询重新检查；其他币种继续处理 |
| 已有持仓无法可靠估值 | 暂停整个组合增加仓位，仍核对持仓和处理有可用 K 线的止损更新 |
| 下单结果不明确、订单未决、止损核验未完成或持仓不一致 | 保留订单记录，异常暂停，人工核查后恢复；不会自动重发写入请求 |
| 启动时已经尝试设置杠杆，随后核验失败 | 暂停并要求核查，不自动重放初始化写入 |
| 网页服务意外消失 | 所属策略子进程检测父进程变化，完成当前操作后退出 |
| 网页请求卡住 | 请求有超时限制；状态刷新后可以继续操作，不会自动重发启动或下单请求 |

信号仍然以所选周期的已收盘 K 线为准，超过 120 秒的开仓信号跳过。若一根 K 线已被消费后才出现异常，本轮信号不会补单。同一根 K 线不会因重连而重复开仓。

事件日志达到约 5 MiB 后轮转，保留 5 份历史文件；订单与持仓状态保存在独立 JSON 文件中，不参与日志轮转。日志归档需要更长保留期时应定期备份。

异常暂停后先对照 OKX 核查持仓、普通挂单、止损单和网页日志，确认处理妥当后，再在对应服务的终端运行：

```sh
pyramid-okx clear-halt
```

本地未激活虚拟环境时使用 `.venv/bin/pyramid-okx clear-halt`。自定义配置或状态目录时沿用启动参数；模拟盘添加 `--demo`。不要通过删除交易状态文件解除暂停。

## 验证范围与边界

自动测试覆盖模拟交易、断网恢复、价差恢复、币种隔离、资金限制、重复订单保护、日志轮转、状态重启、进程退出，以及本地 HTTP / Render Waitress 的认证和控制接口。测试不发送真实订单。

这些检查不能保证网络和交易所永不中断，也不保证跳空后的止损成交价格。股票永续仍使用同一套趋势策略，没有增加股票交易时段或财报日过滤。Render 实际部署还需在所选地区验证 API 可达性、IP 白名单、环境变量和磁盘挂载。
