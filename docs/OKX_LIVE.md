# OKX 永续合约运行说明

本模块接入 OKX V5 的 USDT 线性永续合约，使用原项目的多头突破、金字塔加仓和结构/ATR 移动止损逻辑。实盘需明确点击网页“启动实盘交易”或使用 `run --live` 启动。

## 当前配置

- 周期和杠杆按网页保存的参数或 TOML 配置执行；只做多、逐仓；需要 OKX 单向持仓模式（net mode）。
- 首次启动按最近 24 小时基础币成交量 × 最新价估算 USDT 成交额，选择前 5 个正常交易的加密资产合约，自动模式按 OKX 官方产品分类排除股票、大宗商品、外汇及盘前产品；手动选择支持加密货币、股票和贵金属类别（例如 XAU、SNDK、CRCL），不支持外汇或盘前合约。不是社交热度排名。
- 币对写入状态文件，重启沿用；运行期间不自动轮换。可以在首次启动前通过 `instruments` 指定币对。
- 账户 USD 总权益按 OKX 返回的 USDT 权益估值折算为 USDT。总额度取「首次启动折算权益 × 配置比例」和「当前折算权益 × 配置比例」较小者，包含保证金和双边手续费预留，所选币对平分；可用 USDT 余额不足时进一步缩小。
- 额度是新增订单的约束。持仓价格、资金费、手续费和账户权益变化可能使事后比例超过配置上限，程序不会为比例变化自动减仓。
- 名义仓位上限随资金比例和杠杆变化，例如 20% 资金比例与 2 倍杠杆对应约 40% 本金。实际张数同时受止损距离、1% 单币策略额度风险预算、四档权重、最小交易单位限制。
- 例：账户权益约 1,000 USDT，策略总额度最多 200 USDT，每个币对最多 40 USDT 保证金及费用预留；每笔完整交易的目标风险预算为 0.4 USDT，首档为 0.12 USDT。余额较小时，一些币对会因最小张数而跳过。
- `initial_cash` 是回测参数；实盘使用账户权益，不会把回测的 100,000 当成真实余额。实盘上限由网页保存的参数管理，未保存时使用 `config/okx.toml`。

## API 凭据

在 OKX 创建具有读取和交易权限的 API Key。运行器不需要提币权限，不提供提币、转账或借贷功能。可在 OKX 配置 IP 白名单。建议使用专用子账户；首次启动要求无已有持仓和挂单，避免接管其他策略。运行期间不要在同一账户手动下单或运行另一套策略。

账户应设置为合约模式或跨币种保证金模式，以及单向持仓；关闭自动借币。程序不会切换账户模式。启动 `run` 后才会设置并验证选中币对的配置杠杆（逐仓）。

直接运行 `pyramid-okx` 或部署 Render 时，API 密钥仅从运行时环境变量读取：

| 环境 | API Key | Secret Key | Passphrase |
| --- | --- | --- | --- |
| 实盘 | `OKX_API_KEY` | `OKX_API_SECRET` | `OKX_API_PASSPHRASE` |
| 模拟盘 | `OKX_DEMO_API_KEY` | `OKX_DEMO_API_SECRET` | `OKX_DEMO_API_PASSPHRASE` |

在启动命令行或 Render 网页服务前，将所选环境的三个变量注入进程环境；这些入口不自动加载 `.env`，不读取密钥文件。本地网页可自动读取已保存的密钥，见 [本地网页说明](WEB.md)。网页服务启动后新增或更改环境变量，需要重新启动网页服务。不要将真实值写入代码、策略配置、日志或 shell 历史，也不要把密钥发到聊天或提交 Git。

三个变量必须全部非空，缺失时在连接 OKX 前报错；实盘与模拟盘互不回退。

地区域名在 `config/okx.toml` 中的 `base_url` 设置，须使用账户对应的 OKX 官方 API 域名；不要通过未知代理提交 API 凭据。

## 检查与启动

```bash
# 公共行情及币对筛选，不需要密钥，不下单
pyramid-okx scan

# 只读认证、余额、账户模式和持仓检查，不设置杠杆、不下单
pyramid-okx check

# 明确启动实盘
pyramid-okx run --live

# 只读本地运行状态
pyramid-okx status
```

默认每 10 秒检查已有持仓和止损，只处理已确认收盘的 K 线。空仓币种不会因为新 K 出现而自动扫描首笔开仓信号。首笔开仓有两种人工入口：① 点击“生成候选”后，从符合策略入场信号的候选中确认；② 在“指定币种开仓”中直接选择当前 worker 已管理且无持仓的币种。指定币种开仓不要求该币满足候选信号，但 worker 仍会读取最新已确认收盘 K 线，计算结构/ATR 初始止损，重新核验当前盘口、资金预算、最小张数与交易所状态，通过后才提交带价格上限的 FOK 全成全撤限价单，并附加交易所端止损。首笔成交并确认止损后，该币种进入同一套 position 状态，后续金字塔加仓、保本、移动止损和退出由策略自动接管。

独立的 OKX 模拟盘凭据、状态和接口标志：

```bash
# 设置上述三个 OKX_DEMO_API_* 环境变量后：
pyramid-okx check --demo
pyramid-okx run --demo
pyramid-okx status --demo
```

模拟盘只读取 `OKX_DEMO_API_*` 环境变量。不能混用实盘和模拟盘密钥。

## 执行和恢复

- 每档开仓附带 OKX 交易所端止损。完全成交后查询止损是否实际生效，不能只相信下单返回成功。
- 未能确认止损、或出现意外部分成交时，代码会尝试用 reduce-only 市价单平掉该币对持仓，然后停止，要求人工检查。网络中断或交易所故障也可能使此尝试失败，应直接在 OKX 查看持仓和止损。
- 止损上调逐档修改并确认，修改失败不主动撤销旧止损。止损触发使用最新成交价，触发后按市价执行，不能保证成交价等于止损价。
- 新订单发送前先把意图写盘。写请求不自动重试；结果不明会停止。重启按原客户端订单号核对，查不到也不会重新发送。不要为了恢复而删除状态文件。
- 状态发现不属于本策略的仓位、数量不符、模式不符或配置/账户变化时停止。部分止损成交造成数量差异时也会停止，需要核对剩余止损和仓位。
- `state/okx-live.json` 保存仓位和待确认订单；对应 `.events.jsonl` 保存事件。模拟盘使用独立文件。文件锁防止同一个项目状态被两个进程同时操作。
- Ctrl-C / SIGTERM 请求有序停止：当前订单先完成核对与保护，不再发起新入场；已有仓位和交易所端止损继续保留，退出后移动止损不再更新。
- 运行异常会写入 `.halted.json` 暂停标记。重启不会自动恢复交易；检查并解决问题后，执行 `pyramid-okx clear-halt`，再手动重启。该命令保留原有仓位和订单状态。
- 未配置后台自启动。电脑休眠或程序退出期间无法加仓或更新移动止损，交易所端已生效的止损仍由 OKX 管理。

## 范围与边界

真实账户权限、地区限制、成交、止损挂单与资金费需要在对应账户和实际运行环境中自行核验。

本模块没有把资金费率、强平过程或真实盘口成交反向加入原回测，所以原回测结果不能直接视为永续合约实盘表现。

官方接口依据：[OKX V5 API](https://www.okx.com/docs-v5/en/)；[订单处理指南](https://www.okx.com/docs-v5/trick_en/)。
