# OKX 永续合约运行说明

本模块接入 OKX V5 的 USDT 线性永续合约，使用原项目的多头突破、金字塔加仓和结构/ATR 移动止损逻辑。实盘启动命令需要用户在本地执行。

## 当前配置

- 1H 周期、只做多、逐仓、2 倍杠杆；需要 OKX 单向持仓模式（net mode）。
- 首次启动按最近 24 小时基础币成交量 × 最新价估算 USDT 成交额，选择前 5 个正常交易的加密资产合约，按 OKX 官方产品分类排除股票、大宗商品、外汇及盘前产品。不是社交热度排名。
- 币对写入状态文件，重启沿用；运行期间不自动轮换。可以在首次启动前通过 `instruments` 指定币对。
- 账户 USD 总权益按 OKX 返回的 USDT 权益估值折算为 USDT。总额度取「首次启动折算权益 × 20%」和「当前折算权益 × 20%」较小者，包含保证金和双边手续费预留，5 个币对平分；可用 USDT 余额不足时进一步缩小。
- 额度是新增订单的约束。持仓价格、资金费、手续费和账户权益变化可能使事后比例超过 20%，程序不会为比例变化自动减仓。
- 2 倍杠杆对应约 40% 本金的名义仓位上限。实际张数同时受止损距离、1% 单币策略额度风险预算、四档权重、最小交易单位限制。
- 例：账户权益约 1,000 USDT，策略总额度最多 200 USDT，每个币对最多 40 USDT 保证金及费用预留；每笔完整交易的目标风险预算为 0.4 USDT，首档为 0.12 USDT。余额较小时，一些币对会因最小张数而跳过。
- `initial_cash` 是回测参数；实盘使用账户权益，不会把回测的 100,000 当成真实余额。实盘上限独立由 `config/okx.toml` 管理。

## API 凭据

在 OKX 创建具有读取和交易权限的 API Key。运行器不需要提币权限，不提供提币、转账或借贷功能。可在 OKX 配置 IP 白名单。建议使用专用子账户；首次启动要求无已有持仓和挂单，避免接管其他策略。运行期间不要在同一账户手动下单或运行另一套策略。

账户应设置为合约模式或跨币种保证金模式，以及单向持仓；关闭自动借币。程序不会切换账户模式。启动 `run` 后才会设置并验证选中币对的 2 倍逐仓杠杆。

直接编辑本地配置文件 `config/okx.credentials.toml`，在 `[live]` 区填写实盘凭据：

```toml
[live]
api_key = "你的 API Key"
api_secret = "你的 Secret"
passphrase = "创建 API 时设置的 Passphrase"
```

本机已创建空白配置文件，权限为 600，并被 Git 忽略。新克隆项目可复制 `config/okx.credentials.example.toml` 为 `config/okx.credentials.toml`，再执行 `chmod 600 config/okx.credentials.toml`。请保留示例文件为空，只在本地凭据文件填写真实值。

已填写的配置优先于环境变量和旧 JSON 凭据；当前环境的三个字段必须完整。当前环境的配置为空或文件不存在时，仍兼容环境变量 `OKX_API_KEY`、`OKX_API_SECRET`、`OKX_API_PASSPHRASE` 和旧文件 `secrets/okx-live.json`。旧的 `pyramid-okx credentials` 命令仍可用于创建该 JSON 文件。不要把密钥发到聊天或提交 Git。

地区域名在 `config/okx.toml` 中的 `base_url` 设置，须使用账户对应的 OKX 官方 API 域名；不要通过未知代理提交 API 凭据。

## 检查与启动

```bash
# 公共行情及币对筛选，不需要密钥，不下单
pyramid-okx scan

# 只读认证、余额、账户模式和持仓检查，不设置杠杆、不下单
pyramid-okx check

# 用户在本地明确启动实盘
pyramid-okx run --live

# 只读本地运行状态
pyramid-okx status
```

默认每 10 秒检查仓位和止损，只处理已确认收盘的 K 线。入场仅在收盘后 120 秒内评估；中途启动会跳过过期入场信号。由于真实网络、轮询和盘口，成交价不是回测中精确的下一根开盘价。入场使用带价格上限的 FOK 全成全撤限价单，可能不成交。

独立的 OKX 模拟盘凭据、状态和接口标志：

```bash
# 在 config/okx.credentials.toml 的 [demo] 区填写模拟盘凭据后：
pyramid-okx check --demo
pyramid-okx run --demo
pyramid-okx status --demo
```

模拟盘读取同一配置文件的 `[demo]` 区，字段同样为 `api_key`、`api_secret`、`passphrase`。该区为空时，兼容 `secrets/okx-demo.json` 或 `OKX_DEMO_API_KEY`、`OKX_DEMO_API_SECRET`、`OKX_DEMO_API_PASSPHRASE`。不能混用实盘和模拟盘密钥。

## 执行和恢复

- 每档开仓附带 OKX 交易所端止损。完全成交后查询止损是否实际生效，不能只相信下单返回成功。
- 未能确认止损、或出现意外部分成交时，代码会尝试用 reduce-only 市价单平掉该币对持仓，然后停止，要求人工检查。网络中断或交易所故障也可能使此尝试失败，应直接在 OKX 查看持仓和止损。
- 止损上调逐档修改并确认，修改失败不主动撤销旧止损。止损触发使用最新成交价，触发后按市价执行，不能保证成交价等于止损价。
- 新订单发送前先把意图写盘。写请求不自动重试；结果不明会停止。重启按原客户端订单号核对，查不到也不会重新发送。不要为了恢复而删除状态文件。
- 状态发现不属于本策略的仓位、数量不符、模式不符或配置/账户变化时停止。部分止损成交造成数量差异时也会停止，需要核对剩余止损和仓位。
- `state/okx-live.json` 保存仓位和待确认订单；对应 `.events.jsonl` 保存事件。模拟盘使用独立文件。文件锁防止同一个项目状态被两个进程同时操作。
- Ctrl-C / SIGTERM 请求有序停止：当前订单先完成核对与保护，不再发起新入场；已有仓位和交易所端止损继续保留，退出后移动止损不再更新。
- 运行异常会写入 `.halted.json` 暂停标记。重启不会自动恢复交易；检查并解决问题后，执行 `pyramid-okx clear-halt`，再手动重启。该命令保留原有仓位和订单状态。
- 未配置后台自启动。电脑休眠或程序退出期间无法加仓或更新移动止损，交易所端已生效的止损仍由 OKX 管理。

## 验证范围

单元测试使用离线 OKX 响应，覆盖签名、环境隔离、只读保护、行情确认、资金及张数限制、订单恢复和止损异常。真实账户权限、地区限制、成交、止损挂单与资金费只能通过对应账户进一步验证；测试通过不代表已完成真实成交验证。

本模块没有把资金费率、强平过程或真实盘口成交反向加入原回测，所以原回测结果不能直接视为 2 倍永续合约实盘表现。

官方接口依据：[OKX V5 API](https://www.okx.com/docs-v5/en/)；[订单处理指南](https://www.okx.com/docs-v5/trick_en/)。
